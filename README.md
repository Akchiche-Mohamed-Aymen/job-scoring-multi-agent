# AI-Powered CV Job Matching System

An end-to-end AI-powered CV matching system designed to evaluate a candidate's CV against a job description using a **multi-agent architecture**,**LLM(Mistaral)**, **document chunking**, **embeddings**, **vector search**, and **Retrieval-Augmented Generation (RAG)**.

The project focuses on building the complete AI pipeline, from processing unstructured CV documents to generating structured job requirements and evaluating the candidate against them.

---

## Project Goal

The main goal of this project is to explore and implement an AI-based approach for CV-to-job matching while working with real-world, semi-structured documents.

The project focuses particularly on:

* Multi-agent AI architecture
* PDF document processing
* Different document chunking strategies
* Text embeddings
* Vector databases
* Semantic retrieval
* Retrieval-Augmented Generation (RAG)
* Evidence-based CV evaluation
* LLM-based reasoning
* Backend API development
* Frontend integration

Rather than implementing the matching logic as a single LLM prompt, the system separates different responsibilities into specialized components and agents.

# Multi-Agent Architecture

The core of the project is based on a multi-agent architecture where different agents have different responsibilities.

## HR Agent

The HR Agent is responsible for analyzing the job description.

It transforms the job description into a set of evaluation questions that can be used to assess the candidate.

The generated questions are organized around areas such as:

* Job requirements
* Experience
* Technical skills
* Soft skills
* Education and certifications
* Other requirements

The HR Agent also determines whether a requirement is a **must-have** or a **nice-to-have** and defines the criteria that should be used when evaluating the candidate.

An important design principle is that the HR Agent must only use requirements actually present in the job description rather than inventing additional requirements.

---

## CV Agent

The CV Agent is responsible for answering the evaluation questions generated by the HR Agent.

Instead of sending the complete CV directly to the LLM, the agent uses the indexed CV and performs retrieval to find the most relevant information.

The process is approximately:

```text
Evaluation Question
        ↓
Query Vector Database
        ↓
Retrieve Relevant CV Chunks
        ↓
Provide Retrieved Evidence to LLM
        ↓
Generate CV-Based Answer
        ↓
Evaluate Evidence
```

This allows the system to ground its answers in the actual content of the candidate's CV.

The CV Agent is also designed to preserve the retrieved evidence rather than allowing the LLM to modify or fabricate document content.

If relevant evidence cannot be retrieved, the system can explicitly indicate that the available documents do not provide enough information to answer the question.

---

# Document Processing

CVs are semi-structured documents.

Unlike highly standardized datasets, different CVs can contain different layouts, section names, ordering, and amounts of information.

Because of this, the project explores multiple approaches to document chunking.

## PDF Processing

The CV is first extracted from the PDF and transformed into text that can be processed by the retrieval pipeline.

The extracted content is then divided into smaller chunks before being converted into embeddings.

---

# Chunking Strategies

Three different approaches were explored in the project.

## 1. Character-Based Chunking

Character-based chunking is used as a baseline.

The document is divided according to a fixed amount of text.

```text
CV
 ↓
Fixed-size chunks
 ↓
Embeddings
 ↓
Vector Database
```

This approach is simple and predictable, but it does not necessarily respect the semantic structure of a CV.

For example, information belonging to the same section can potentially be separated between chunks.

---

## 2. Semantic Chunking

Semantic chunking attempts to divide the document according to the meaning of the text rather than using only a fixed size.

The system compares the semantic relationship between consecutive pieces of text and uses these relationships to determine where a new chunk should begin.

The goal is to create chunks containing information that is more semantically coherent.

```text
CV Text
   ↓
Text segments
   ↓
Semantic similarity
   ↓
Semantic boundaries
   ↓
Meaningful chunks
```

This approach is particularly interesting for CVs because related information can span different amounts of text.

---

## 3. Agentic Chunking

The project also explores an agentic approach to chunking.

Instead of relying only on predefined chunking rules, an LLM-based component can analyze the document and determine how its content should be divided.

The idea is to allow the system to consider the actual structure and meaning of the document when creating chunks.

```text
CV
 ↓
LLM analysis
 ↓
Identify meaningful sections
 ↓
Create chunks
 ↓
Generate embeddings
 ↓
Store in vector database
```

This approach is more flexible for semi-structured documents such as CVs, where there is no guaranteed universal schema.

---

# Embeddings

After chunking, the text chunks are transformed into vector representations using embedding models.

These embeddings allow the system to represent the semantic meaning of the CV content numerically.

The resulting vectors are stored in a vector database and later used for similarity search.

The project experimented with different embedding approaches during development, including:

* Hugging Face embeddings
* Mistral embeddings

The embedding layer is separated from the retrieval and agent logic, making it possible to change the embedding model without redesigning the complete architecture.

---

# Vector Database

The project uses **ChromaDB** as the vector database.

The general pipeline is:

```text
CV
 ↓
Text Extraction
 ↓
Chunking
 ↓
Embeddings
 ↓
ChromaDB
```

During matching:

```text
Question
 ↓
Question Embedding
 ↓
Similarity Search
 ↓
Relevant CV Chunks
```

The retrieved chunks are then passed to the CV Agent as evidence for answering the evaluation question.

---

# Retrieval-Augmented Generation

RAG is one of the central components of the system.

Instead of relying entirely on the LLM's internal knowledge, the CV Agent retrieves information directly from the candidate's CV.

The process can be summarized as:

```text
Question
   ↓
Embedding
   ↓
Vector Search
   ↓
Relevant CV Content
   ↓
LLM
   ↓
Grounded Answer
```

This makes the evaluation more closely connected to the actual candidate document.

The retrieval layer also makes it possible to provide the source documents used for an answer, which is important for traceability.

---

# Evidence-Based Evaluation

Each generated answer is associated with information describing the quality and availability of the supporting evidence.

The system considers factors such as:

* Whether relevant information was found
* How strongly the retrieved content supports the requirement
* Which documents were retrieved
* The confidence associated with the individual evaluation

This creates a distinction between:

### Overall CV Score

The final evaluation of the candidate against the job.

### Question-Level Confidence

The confidence associated with an individual requirement evaluation.

This separation prevents the individual retrieval/evaluation confidence from being confused with the final CV matching score.

# Backend

The backend is implemented using **FastAPI**.

It exposes API routes that connect the frontend to the AI pipeline.

The main workflow is divided into four operations:

```text
CV Ingestion
     ↓
API Configuration
     ↓
Job Structuring
     ↓
CV Matching
```

## Main Routes

### Ingest CV

```text
POST /v0/ingest_documents
```

Processes and indexes the candidate CV.

### Add API Keys

```text
POST /v0/api_key
```

Stores the API credentials required by the AI components.

### Structure Job

```text
POST /v0/job-profile
```

Processes the job title and description and creates the structured job profile.

### Match CV

```text
POST /v0/match_cv
```

Runs the complete matching pipeline and returns the final evaluation.

# End-to-End Workflow

The complete system works as follows:

### Step 1 — CV Ingestion

The user provides a candidate PDF.

The backend extracts the document content and prepares it for indexing.

### Step 2 — Chunking

The extracted CV content is divided into chunks using the selected chunking strategy.

### Step 3 — Embedding

Each chunk is converted into a vector representation.

### Step 4 — Vector Storage

The embeddings and associated document content are stored in ChromaDB.

### Step 5 — Job Analysis

The HR Agent analyzes the job description and generates evaluation questions.

### Step 6 — Retrieval

For each question, the CV Agent queries the vector database to retrieve relevant CV content.

### Step 7 — LLM Evaluation

The retrieved information is provided to the LLM, which evaluates the candidate based on the HR Agent's criteria.

### Step 8 — Final Matching

The system combines the individual evaluations into a final CV-to-job matching result.

## Backend

1. Download The project:

```bash
git clone https://github.com/Akchiche-Mohamed-Aymen/job-scoring-multi-agent.git
```
